# ADR-002：交互组拥有独立视觉关键状态

- 状态：已接受
- 日期：2026-08-14

## 背景

人物拿杯子、喝水、穿鞋等动作包含成员之间的接触、遮挡和归属变化。若分别生成人物与物品关键帧，手指、物体和接触阴影很难准确对齐；若把联合生成结果覆盖到人物元素，又会破坏可复用的原始资产。

## 决策

1. `InteractionGroup` 可以拥有自己的视觉关键帧集合。
2. 交互关键帧描述的是组内所有成员在某一时刻的联合视觉状态。
3. 接受的联合生成结果写入交互组关键帧，不覆盖成员元素关键帧。
4. 在交互区间内，已接受的交互图层优先于成员原始图层显示；组外背景和前景仍保持锁定。
5. 过渡视频连接交互组中已接受并锁定的首尾关键帧。
6. 模型、供应商参数和密钥仍只存在于 Adapter 与生成记录中。
7. 交互区间内，成员元素的选择与新增关键状态操作代理到交互组；元素数据本身不被替换。
8. 成员元素时间轴保留但显示“交互接管”覆盖区，区间内的独立关键帧不参与编辑或播放。
9. 同一元素在同一时间最多由一个交互组接管；重叠交互必须调整区间或合并为同一交互组。

## 当前限制

MVP 的 Qwen 输出是完整 RGB 合成图。后续接入蒙版后，交互关键帧应保存透明图像或配套蒙版，以便只覆盖交互区域。

## 结果

- 人物与物品资产仍可独立复用。
- 接触关系由同一次图像生成完成。
- 交互失败可以局部重做，不污染成员元素。
- 在蒙版闭环完成前，已接受的交互图层会暂时以整帧图像预览。
