# ADR-009：锚点式动作组领域契约与分阶段验收

- 状态：已接受
- 日期：2026-08-16

## 背景

ADR-007/008 建立了“关键帧优先”的方向，但没有完整区分动作与互动、首帧可见状态与动作意图、描述节点与视频边界，也没有把跨字段一致性落实为校验。旧 SH001 不再是兼容目标；SH002 和锚点式结构是唯一基线。

## 决策

1. `InteractionGroup.kind` 必须显式为 `action` 或 `interaction`。动作组恰好一个成员；互动组至少两个成员，成员去重。
2. `anchorKeyframeId` 必填。锚点必须唯一存在于成员元素轨道，帧号等于组起点，一个锚点只能拥有一个有效组。
3. 锚点 `instruction` 只描述当前可见状态；组 `instruction` 保存动作意图。Planner 分开接收 `anchorDescription` 和 `actionIntent`。
4. 组内关键帧只保存锚点之后的状态，帧号唯一、严格递增，并位于所有成员有效区间的交集内。
5. `VisualKeyframe` 用供应商中立字段表达节点身份：
   - `renderPolicy`: `required | optional | extractFromVideo`；
   - `generationBoundary`: 是否为视频生成边界；
   - `sourceKind`: `authored | generatedImage | acceptedVideoFrame`。
6. 锚点必须有图片；组尾必须是生成边界。描述型中间节点可以没有图片，已有规划图也不会自动成为视频边界。
7. 默认整组提示词由动作意图、按时间排序的可见状态和连续性约束编译，供应商 Adapter 只消费编译结果。
8. 拖动锚点或派生节点必须通过统一时间更新函数，同步组范围与关联 Transition；已采用媒体解除当前选择并标为归档，但文件不物理删除。
9. 新建编辑会话默认使用 `wan-i2v-2.7`。缺少旧字段不得回退到 Wan 2.2。
10. SH001 不迁移、不参与模型或回归验收，并从默认镜头列表隐藏；其历史目录暂不物理删除。
11. 动作组范围由后端在调用 Planner 前确定。普通动作默认 2 秒（24 fps 时 48 帧），作者可在规划前调整；Planner 必须接收 `desiredDurationFrames`、`targetEndFrame` 和 Wan 允许的 2–15 整数秒范围，且最后状态必须落在目标结束帧。
12. 每次成功规划保存不可变历史：Planner 标识、后端最终原始请求、语言模型原始文本回复及解析结果。删除动作组或重新规划不得删除这些历史。
13. Wan 提示词使用组内 0%–100% 相对时间，逐节点包含动作意图、可见状态、`transitionToNext`、`phase`、`holdFrames` 和 `continuity`。后端报价阶段重新编译最终提示词，避免前端旧文本成为实际请求。
14. 动作组规划完成不等于可生成视频。只有锚点和尾边界图片均已采用时才可提交；尾帧图片与 Wan 视频均须作者确认，Wan 提交预览显示首尾图、最终提示词、时间轴时长、整数请求秒数、速度比例和预计费用。
15. SH003 保留为重复锚点的无效审计样例，通过标记从正常镜头列表隔离，不迁移、不参与付费生成。

## 审查报告 15 条验收条件的里程碑归属

### 本里程碑 A 已实现

- 规则 1：锚点归属、起点一致和唯一所有权校验。
- 规则 3：组内帧唯一、递增和成员有效区间交集校验。
- 规则 4：显式动作/互动类型。
- 规则 6 的领域部分：显式图片策略、生成边界和来源类型。
- 规则 7 的数据基础：四种界面身份所需字段已存在；完整节点操作 UI 归 C。
- 规则 11 的输入边界：Planner 分开接收动作意图与锚点可见状态。
- 统一组时间更新、锚点式首尾帧解析、第一个派生图使用锚点连续性参考。

### 里程碑 B：整组生成与付费保护（已实现）

- 规则 8：默认整组生成，仅在显式边界拆段；拓扑风险只做建议，由作者确认。已实现边界驱动的 Transition 重建及组级提示词编译。
- 规则 9：相同素材与参数的付费任务去重、进行中和成功历史提示。已通过稳定请求指纹在提交前拦截。
- 规则 10：输出时长与时间轴时长超过 2 倍时阻止或明确确认。已由后端报价校验和前端确认共同保证。
- 生成前展示模型、时间轴时长、请求时长/段数和预计费用。已实现先报价、再携带报价指纹提交的两阶段流程。

### 里程碑 C：动作与互动 UI、规划质量和质检

- 规则 2：删除锚点级联删组；删除组保留锚点；媒体归档。当前本地级联与时间变更归档已具备，删除确认和统一后端命令待完成。
- 规则 5：互动组任意成员多选及独立联合层；后端请求已使用成员列表，完整多选 UI 和动作层输出语义待完成。
- 规则 7：节点身份标识，以及生成图片、切换边界、抽取实际帧、删除节点操作。
- 规则 12：规划覆盖预备、主动作、完成、反应/保持及合理保持帧数。
- 规则 13：多个完整动词拆组、错峰/重叠、运动弧线和缓入缓出。
- 规则 14：左右手、朝向、归属、接触、支撑、穿戴的结构化连续性检查。
- 规则 15：身份、左右手、肢体、背景、速度质检及拒绝原因保存。

当前进度：动作/互动文案和输出语义已分流；互动对象请求与界面支持任意数量成员；节点可显示“仅描述 / 有规划图 / 强制边界 / 视频实际抽帧”，并支持生成图片、切换边界、免费抽帧和删除；删除节点与组均明确保留历史媒体。

规则 12–15 的基础约束也已落地：Planner 输出必须覆盖主动作、完成和保持阶段，保存保持帧数；左右手、朝向、归属、接触、支撑和穿戴进入 `continuity` 结构；规划提示明确限制多个主要变化并要求运动弧线、缓入缓出与屏幕方向连续；生成版本可保存身份、左右手、肢体、背景和速度五项质检，以及拒绝原因。真实模型下的规则阈值仍需后续使用经授权的生成样本调优。

## 结果

新式组不再依靠成员数量或空图片猜测语义，锚点、节点和过渡时间具有可校验的一致性。剩余付费生成、完整多选 UI 和生成后质检必须按上述里程碑继续实现，不能被视为本 ADR 已完成的能力。
