# ADR-008：关键帧优先，动作/互动组从首帧派生并锚定

- 状态：已接受
- 日期：2026-08-15

## 背景

上一版把动作/互动组当作独立容器：先建组（空起止帧）、单独输意图、再规划填组。这导致关键帧只是组的填充物，组可以凭空存在，难以管理。正确的心智模型是：关键帧是一等公民，动作/互动组都从某个关键帧派生、并被它锚定。

## 决策

1. 动作/互动组从「首帧」派生：选中元素上的某个关键帧作为首帧，语言模型读首帧描述，生成首帧之后的剩余关键帧，并自动选择一个结束帧。
2. 首帧留在元素时间轴（`element.keyframes`），组通过 `anchorKeyframeId` 引用它；组的 `keyframes` 只存剩余关键帧（帧号 > 首帧帧号）。
3. 意图 = 首帧描述，不再单独输入意图；单成员 = 动作组，额外选对象 = 互动组。
4. 级联删除：删除首帧 → 整组及对应 transition 一并删除。
5. 规划一步到位：`POST /api/action-groups` 生成剩余关键帧并直接创建组；移除草案/计划存储/两步 apply 机制。

## 结果

作者先有首帧（状态），组从它长出来，删首帧即删组。关键帧是唯一的一等公民，组是可派生、可删除的锚定分组。
