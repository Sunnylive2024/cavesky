# ADR-007：交互组泛化为「动作组」，规划限定到片段内

- 状态：已接受
- 日期：2026-08-15

## 背景

语言模型动作规划第一版是「一句话 → 整镜头自动抓第一个角色＋第一个道具 → 自动挑帧号」，作者无法控制规划的对象和时间范围，难以管理。作者希望先为元素（或元素集合）圈定一个有起止帧的「动作状态」，再在这个片段内让语言模型分配关键帧。

## 决策

1. `InteractionGroup.members` 最小数从 2 放宽到 1：单成员交互组即「单元素动作状态」，2+ 成员仍是交互组；复用现有的 `range`、`keyframes`、时间轴渲染与生成链路。
2. 动作规划从「整镜头」重定向为「片段内」：`POST /api/action-plans` 需要 `groupId`，规划器只拿到该组的 `members` + `range`，关键帧落在 `[range.start, range.end]` 内。
3. `apply` 改为填充目标组：用规划的关键帧替换该组的 `keyframes`、`instruction = intent`；不动 `members`/`range`/`exit`，也不新建 transition。
4. 计划草稿仍作为独立资源持久化（`work/plans/`），`ActionPlan` 记录 `groupId` 以追溯目标组。

## 结果

作者先决定「谁、在哪、多长」，语言模型只负责「在这段里塞哪些关键状态」，规划可控、可局部重做。单元素动作与多元素交互用同一个概念管理，无需在镜头格式外另建平行结构。
