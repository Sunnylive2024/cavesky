# CaveSky 项目上下文

最后更新：2026-08-13

## 一句话定义

CaveSky 是为独立动画创作者打造的本地优先 AI 数字摄影棚：管理固定演员、布景、物品和机位，把作者编排好的镜头转成可分层、可导演、可连续生产的动画。

## 核心工作方式

创作者像使用剪辑软件一样工作：

1. 把背景、人物、物品等资产加入镜头和图层。
2. 每个元素拥有自己的有效区间、时间轴和视觉关键帧。
3. 创作者指定元素在关键帧上的状态。
4. 对“人物拿起杯子”这类接触动作，把人物和杯子组成临时交互组，并描述动作。
5. 图像模型绘制关键状态，视频或动画模型生成状态之间的过渡。
6. 未参与交互的图层只提供空间、光照和遮挡参考，避免被模型重绘。

系统不要求作者维护复杂的专业动画轨道。确定性的位移、缩放等简单变化由编辑器插值；需要形变、接触和语义理解的变化交给 AI。

## 当前 Demo

验证镜头：固定场景中，一名短发女性伸手拿起蓝色杯子。

当前已经具备：

- 本地 React/TypeScript/Vite 编辑器。
- Python/FastAPI/Pydantic 本地服务。
- 本地资产导入和资产库。
- 将资产添加为独立镜头元素。
- 元素选择、Shift 多选、画布拖动、缩放和有效区间调整。
- 独立元素时间轴和视觉关键帧。
- 在播放头添加关键帧、右键删除、左右拖动关键帧。
- 创建交互组，编辑动作描述和起止帧，删除交互动作。
- 保存和重新加载真实 `shot.json`。
- `zichang/` 中的背景、人物和杯子示例资产。

## 技术边界

- 前端：`apps/editor/`，React + TypeScript + Vite。
- 后端：`cavesky/`，Python + FastAPI + Pydantic。
- 示例工程：`examples/pickup-cup/`。
- 测试：`tests/`。
- 通用数据协议不能依赖单一模型供应商。
- MVP 采用本地文件存储，不提前引入数据库。
- 模型通过 Adapter 接入；编辑器只依赖通用生成任务协议。

## 计划中的模型职责

- VACE：基于关键状态、动作描述和蒙版生成局部过渡动画。
- SAM 系列：辅助选择主体或交互区域并产生蒙版。
- RIFE：在需要时提高输出帧率；不能替代语义动作生成。

这些是当前候选方案，不是写死在工程格式中的永久依赖。

## 关键术语

- 元素：背景、人物、物品或前景等可独立管理的视觉对象。
- 视觉关键帧：作者确认或模型生成的元素关键状态。
- 交互组：某个时间区间内需要联合生成的多个元素。
- 过渡任务：连接两个关键状态的动作生成请求。
- 锁定内容：模型无权修改，只能作为上下文参考的内容。

## 产品成功标准

Demo 的首要目标不是界面功能数量，而是证明：固定资产可以复用，人物与物品交互可信，失败片段可以局部重做，并且第二个镜头或第二集的成本明显下降。
